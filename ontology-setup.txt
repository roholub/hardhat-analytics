OPTIONAL: ONTOLOGY BUSINESS CONTEXT

Requirement: Microsoft Fabric Ontology (new experience) is a preview feature.
Availability and permissions depend on your tenant and capacity. Follow current
Microsoft documentation; this sample does not claim general availability.
https://learn.microsoft.com/en-us/fabric/iq/ontology/overview

Create a NEW ontology item in your sample workspace. Use these five concepts:

Entity          Backing table       Key
Project         projects            project_id
Task            task_evidence       task_id
Zone            locations           location_id
CostRecord      costs               cost_id
ProjectReview   project_reviews     review_id

Bind the entity properties to the matching column names and data types.
Describe ProjectReview as derived historical evidence, not a human approval.
Describe completion_evidence as RecordedFinish/NoRecordedFinish.
Explain that risk_score and status thresholds are synthetic.
For name searches, use task_name_search with lowercase input, or LOWER(task_name).

RELATIONSHIPS
TaskBelongsToProject: Task.project_id -> Project.project_id.
TaskLocatedInZone: Task.location_id -> Zone.location_id.
CostRecordForTask: CostRecord.task_id -> Task.task_id.
ZoneBelongsToProject: Zone.project_id -> Project.project_id.
ReviewAssessesProject: ProjectReview.project_id -> Project.project_id.
TaskDependsOnTask: Task -> Task, using mapping table task_dependencies:
  Origin Task.task_id maps to successor_task_id.
  Target Task.task_id maps to predecessor_task_id.

Use the relationship configuration UI to select origin/target properties;
enable the mapping-table option only for TaskDependsOnTask.
Save the bindings and inspect the source mappings. A Task-to-Task loop in the
model canvas describes the relationship type, not a task depending on itself.
The canvas is a schema map, not proof of materialized graph instances.

Do not activate every physical filtering relationship indiscriminately.
Avoid ambiguous filter paths. Source-native SQL is sufficient for these
questions; graph materialization is not required by this replication sample.

Agent guidance:
Use only bound historical sample data. Explain source IDs and definitions.
Aggregate cost records once. Distinguish recorded facts, review prioritization
and unestablished cause. Missing finish dates do not imply active work.
Keep responses concise; show the query on request. Never invent subcontractor,
margin, causal, approval or live-readiness evidence. Evaluate results yourself.
